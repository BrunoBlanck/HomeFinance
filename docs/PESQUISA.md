# Pesquisa de modernização — setembro/2026

Consolidação de três pesquisas na internet (estrutura de IA, API Go, frontend React) que fundamentam as decisões da stack. Cada mudança aplicada nos docs/ADRs referencia esta página.

## 1. Estrutura de trabalho com IA

- **AGENTS.md é padrão aberto** (Agentic AI Foundation/Linux Foundation, 60k+ repositórios, lido por 30+ ferramentas). Adotado: regras universais em `AGENTS.md`, fluxo Claude-específico em `CLAUDE.md` (que importa o primeiro). — [agents.md](https://agents.md/)
- **Context engineering**: CLAUDE.md mínimo ("teste de deleção"); conhecimento detalhado em skills/docs carregados sob demanda (progressive disclosure). — [Anthropic: Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- **Descriptions como regra de roteamento** ("Use quando X; não use quando Y") são a linha de maior alavancagem em agentes/skills; ferramentas mínimas por agente (revisor sem Write) são fronteira de segurança. — [Tembo: Subagents 2026](https://www.tembo.io/blog/claude-code-subagents)
- **Garantia = hook/permissão; conhecimento = skill; delegação = subagente; sempre-necessário = CLAUDE.md curto.** Aplicado: deny de leitura/edição em `.env*` e `secrets/` no settings.json; lembrete de revisão de segurança via hook PostToolUse. — [SmartScope: técnicas avançadas](https://smartscope.blog/en/generative-ai/claude/claude-code-best-practices-advanced-2026/)
- **Spec-driven development** (GitHub Spec Kit): spec → plano → tarefas → implementação, com 60–80% menos retrabalho relatado. Aplicado na versão leve: skill `/especificar` + specs versionadas em `docs/specs/`. — [GitHub Blog: Spec-driven development](https://github.blog/ai-and-ml/generative-ai/spec-driven-development-with-ai-get-started-with-a-new-open-source-toolkit/)
- **Revisão adversarial multi-agente** (revisores com lentes distintas + céticos que tentam refutar + juiz) é padrão maduro — já implementado no workflow `auditoria-seguranca`. — [alexop.dev: Deterministic orchestration](https://alexop.dev/posts/claude-code-workflows-deterministic-orchestration/)
- Futuro: empacotar agentes+skills+hooks como **plugin** versionado para reuso; Agent Teams (experimental) para features full-stack em worktrees paralelos.

## 2. API Go (2025–2026)

- **Go 1.27 atual** (só 1.27/1.26 recebem patches). `encoding/json/v2` virou o padrão: parsing mais rápido e **mais estrito** (rejeita UTF-8 inválido e chaves duplicadas — ganho de segurança grátis). — [go.dev/doc/go1.27](https://go.dev/doc/go1.27)
- **Roteador**: stdlib `net/http.ServeMux` (método + wildcards desde 1.22) é a recomendação minimalista; chi se precisar de middlewares prontos (100% compatível). golang-standards/project-layout **não é oficial** — o guia oficial é [go.dev/doc/modules/layout](https://go.dev/doc/modules/layout); tendência: `internal/` **por domínio**, não por camada técnica. — [encore.dev](https://encore.dev/articles/best-go-backend-frameworks)
- **Bibliotecas padrão de fato**: `golang-jwt/jwt/v5` (⚠️ `dgrijalva/jwt-go` está **abandonada** — nunca usar); go-playground/validator v10; `log/slog`; config com caarlos0/env (viper considerado pesado/bugado; koanf v2 é o substituto se precisar de arquivos).
- **Dados multi-banco**: **sqlc eliminado — não suporta SQL Server**. Opções com os 4 dialetos: `database/sql` + **sqlx** (scan em structs, controle total) ou **Bun** (query builder que traduz dialetos). GORM desaconselhado (overhead/mágica). — [docs.sqlc.dev](https://docs.sqlc.dev/en/latest/howto/generate.html), [bun.uptrace.dev/guide/drivers.html](https://bun.uptrace.dev/guide/drivers.html)
- **Migrações**: **goose v3** — SQL puro, suporta Postgres/MySQL/SQLite/**MSSQL**, embutível via `embed.FS` (migra no boot, sem CLI no deploy). — [pressly.github.io/goose](https://pressly.github.io/goose/)
- **Segurança**: OWASP API Security Top 10 vigente é 2023; nº 1 é **BOLA** (autorização por objeto — exatamente a regra do `household_id`). Rate limit com `golang.org/x/time/rate`. **govulncheck + gosec** no CI ([go.dev/doc/security/best-practices](https://go.dev/doc/security/best-practices)). Access token 10–15 min para apps financeiros; **refresh opaco (não JWT), hash no banco, rotação com invalidação de família**. **Passkeys/WebAuthn** é a tendência dominante (lib: `go-webauthn/webauthn`).
- **OpenAPI**: escrever spec à mão depois do código é legado (swaggo idem). Moderno: **spec-first com oapi-codegen** (spec 3.1 versionada gera tipos/stubs/validação) ou Huma v2 (handlers tipados geram spec). — [huma.rocks](https://huma.rocks/), [appliedgo.net](https://appliedgo.net/spotlight/4-tools-for-generating-rest-apis/)
- **Testes**: table-driven + `t.Run`; httptest; **testcontainers-go** para rodar a mesma suíte de repositório nos 4 bancos reais; `go test -race` sempre. — [golang.testcontainers.org](https://golang.testcontainers.org/)

## 3. Frontend React (2025–2026)

- **React 19.2** (Actions/`useActionState`, `use()`, `useOptimistic`, `<Activity>`, `useEffectEvent`) — tudo funciona em SPA; Server Components irrelevantes para Vite SPA. `<ViewTransition>` do React ainda é experimental — usar a **View Transitions API do navegador** (baseline). — [react.dev](https://www.react.dev/blog/2025/10/01/react-19-2)
- **Vite 8** com Rolldown (builds 10–30× mais rápidos; Node 20.19+). — [vite.dev/blog/announcing-vite8](https://vite.dev/blog/announcing-vite8)
- **TanStack Router > React Router v7 para SPA**: rotas e **search params 100% tipados** (ideal para filtros `?mes=2026-09&categoria=...` validados com Zod), loaders integrados ao Query. TanStack Query v5: `queryOptions` co-locados + `useSuspenseQuery`. — [devtoolbox: comparativo 2026](https://devtoolbox.blog/tanstack-router-vs-react-router-v7-2026/)
- **Estrutura bulletproof-react**: `src/app` + `src/features/<feature>` + camada shared; **imports entre features proibidos** (ESLint `import/no-restricted-paths`); **sem barrel files** (tree-shaking). — [bulletproof-react](https://github.com/alan2207/bulletproof-react/blob/master/docs/project-structure.md)
- **Lint/format**: **Biome** (10–25× mais rápido, um binário) + typescript-eslint mínimo só para regras type-aware; TS `strict` + `noUncheckedIndexedAccess`. — [Better Stack: Biome vs ESLint](https://betterstack.com/community/guides/scaling-nodejs/biome-eslint/)
- **CSS baseline seguro em produção**: nesting nativo, `:has()`, container queries, subgrid, `@layer`, **OKLCH + `color-mix()`** (estados derivados: `color-mix(in oklch, var(--accent), transparent 85%)`), View Transitions same-document, **Popover API** (baseline desde abr/2025). CSS Modules segue escolha sólida; **DTCG 2025.10** é o formato padrão de tokens se um dia precisar exportar. — [modern-css.com](https://modern-css.com/whats-new/), [designtokens.org](https://www.designtokens.org/tr/drafts/format/)
- **Acessibilidade**: voltar ao HTML nativo — `<dialog>` para modais (foco/ESC/inert grátis), Popover API para menus (light dismiss/foco grátis, mas role semântica e setas são suas), WAI-ARIA APG para combobox/tabs. — [hidde.blog](https://hidde.blog/dialog-modal-popover-differences/)
- **Anti-"cara de IA"**: assinaturas do slop = gradiente roxo→azul, glassmorphism, Inter em tudo, grids de 3 cards, estados vazios não desenhados, foco invisível. Antídotos: tipografia com personalidade (alavanca nº 1), paleta contida com **cor reservada a estado financeiro** ("trust reads as restraint"), densidade editorial, `tabular-nums` + `slashed-zero` em números. Fintech 2026: calma = credibilidade — validação da identidade "caderno de contas". — [SmoothUI: AI design slop](https://smoothui.dev/blog/ai-design-slop), [Eleken: fintech trust patterns](https://www.eleken.co/blog-posts/modern-fintech-design-guide)
- **Formulários**: react-hook-form (validação em tempo real) + **Zod 4** (14× mais rápido) com schema compartilhado entre form, search params e API. **Testes**: Vitest 4 + **Browser Mode** (componentes em navegador real) + Playwright E2E. — [zod.dev/v4](https://zod.dev/v4), [Epic Web: Browser Mode](https://www.epicweb.dev/vitest-browser-mode-vs-playwright)
